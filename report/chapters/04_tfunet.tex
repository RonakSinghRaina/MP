\section{Cause 1: class weighting and the ReLU output}
% Explain the mechanism in your own words -- you presented this in Week 5:
% - tf_unet applies ReLU to its two output scores (unet.py line 145).
% - Class weighting pushes the "clean" score negative; ReLU clamps it to 0;
%   ReLU's gradient at negative input is 0, so it cannot recover.
% - Evidence: run 2 output exactly 0.537 for all 24,840,000 test pixels.
%   softmax(0, c) = 0.537  ->  c = 0.148. The network became a constant.
% - Neither part alone is the problem; the combination is.
% - Nuance: on the v4 dataset the network ESCAPED this state after 15
%   epochs [PART 8] -- so write "very long freeze", not "permanent".

\section{Cause 2: per-image normalisation}
% - Each image scaled by its own min/max; per-image maximum ranges 27 to
%   222 (8.2x) on this dataset.
% - Worked example table [PART 1]: noise (10) and faint RFI (20) in a quiet
%   and a loud image -- noise in the quiet image (0.370) reads brighter than
%   RFI in the loud image (0.090).
% - The authors avoided this themselves: their launcher uses a_min=30,
%   a_max=210. It was lost when the code was adapted.
% - tf_unet has no normalisation layers, so it cannot compensate.
% - Fix: clip to a fixed range measured from the 0.5th/99.5th percentiles of
%   training images only.
