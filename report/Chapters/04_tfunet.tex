\chapter{The \tfunet{} Baseline}
\label{ch:tfunet}

\section{Results on Synthetic Data}
We applied the \tfunet{} code of Akeret et al.\footcite{akeret2017}, which is
publicly available on GitHub, to the 276$\times$600 version of our synthetic
data, the image size used by the authors. The network was used unchanged
(3 levels, 32 filters in the first layer, 465{,}986 parameters), together with
the authors' preprocessing: every image is scaled with one fixed intensity
range, and no class weighting is used. We changed only two things:
\begin{itemize}
  \item \textbf{Batch size: 4 images instead of the paper's 32.} Our graphics
    card has 6\,GB of memory, and with only 4 LOFAR images per batch \tfunet{}
    already uses 4.3\,GB of it, so 32 images do not fit.
  \item \textbf{Optimiser: Adam with a learning rate of $10^{-3}$ instead of
    the paper's momentum gradient descent starting at 0.2.} Both optimisers do the
    same job; Adam also sets the step size for each weight by itself. With only
    a few images per batch, the direction of each step is noisy, so smaller
    steps are safer. In an early test with a different setup (larger images and
    one image per step), the paper's setting made the network stop learning
    after only 4 steps. With Adam the network trained normally, so we used it
    throughout.
\end{itemize}
On the synthetic test set
\tfunet{} reached a maximum \Fone{} of 0.9317, with an AUROC of 0.9908.

\section{Results on LOFAR}
\label{sec:tfunet_lofar}
We then trained \tfunet{} on the real LOFAR data with the same settings: the
unmodified network, fixed-range normalisation and no class weighting. The model was trained on the
6621 clean training images, \hl{the threshold was chosen on 150 of the 735
validation images}, and the result was measured on the 109 images labelled by the human
expert. Each setting was run with three random seeds.

RFI is very rare in these images: in the training set there is only one RFI
pixel for every 123 clean ones. Even so, the network did not take the easy way
out of calling every pixel clean. Trained for as long as on the synthetic data
(60 epochs, learning rate $10^{-3}$), it reached a maximum \Fone{} of
$0.4901 \pm 0.0495$. With a smaller learning rate ($10^{-4}$) and longer
training (150 epochs), it reached $0.5482 \pm 0.0139$ (\cref{tab:tfunet_lofar}).

The lower learning rate also made the result much more consistent between
seeds: the standard deviation of the maximum \Fone{} fell from 0.0495 to
0.0139.

\Cref{fig:tfunet_lofar} compares \tfunet{} with other methods. The values for
Mesarcik et al.'s U-Net and RFI-Net are taken from their
paper\footcite{mesarcik2022}. They report the maximum \Fone{}, so we use the
same score. \tfunet{} does much better than a simple $\sigma$-clipping
threshold (0.4103), but worse than \aoflagger{} (0.5698), and 0.039 worse than
Mesarcik et al.'s U-Net (0.5876). These two U-Nets are not the same network.
Mesarcik et al.\ wrote their own U-Net, with batch normalisation and same
padding, and trained it on small 32$\times$32 pieces of the images. \tfunet{} is
Akeret et al.'s original code, and we trained it on full images.

\subsection{Running Mesarcik et al.'s own code}
\label{sec:mesarcik_rerun}
Mesarcik et al.\ shared their code on GitHub\footnote{\url{https://github.com/mesarcik/RFI-NLN}}.
We ran it with exactly their settings: their own U-Net, the images cut into
small 32$\times$32 pieces, batches of 1024 pieces, 100 epochs and the same
maximum \Fone{} score. The only change was that we removed the 109 test images
from training: their code trains on them, because they are copies of training
images (\cref{sec:lofar_audit}). It scored 0.6166, close to and slightly above
the 0.5876 given in their paper (\cref{fig:mesarcik_rerun}), so we were able to
reproduce their result.

\section{From synthetic to real data}
\label{sec:gap}
The same network, trained with the same settings and the same number of
gradient steps (10{,}500), scores 0.9317 on the synthetic data and 0.4901 on
LOFAR: a drop of 0.44 in \Fone{}. Even the best LOFAR result, after tuning the
learning rate, is 0.38 below the synthetic score. The reasons were set out in
\cref{sec:lofar_harder}: real RFI is far rarer, much of it is fainter than the
noise, and the training labels themselves are often wrong. A method that
performs well on a synthetic benchmark can therefore perform much worse on
real observations, and synthetic results alone should be read with care.
